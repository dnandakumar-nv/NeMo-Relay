# Validate Router with Real Providers

Use this workflow before enabling Router against a new provider deployment. It
supplements the provider-free test matrix with bounded paid calls through the
same family codecs, replay boundary, Judge parser, embedding client, and CLI
host used in production.

This page uses NVIDIA Inference and these pinned model identifiers:

| Role | Model | Endpoint |
|---|---|---|
| Anchor and Judge | `openai/openai/gpt-5.5` | `https://inference-api.nvidia.com/v1` |
| Candidate | `nvidia/deepseek-ai/deepseek-v4-pro` | `https://inference-api.nvidia.com/v1` |
| Embedding | `azure/openai/text-embedding-3-large` | `https://inference-api.nvidia.com/v1/embeddings` |

The embedding model returns 3,072 components. The GPT-5.5 deployment requires
the optional Router Judge setting `temperature = 1.0`; an omitted Judge
temperature retains the default `0.0` behavior.

## Prepare Credentials

Export the credential without placing it in TOML, JSON, command output, test
names, or the Router database:

```bash
export INFERENCE_API_KEY="<provider-key>"
```

Real-provider tests are ignored by default and incur provider charges. Run
them only in an environment authorized to send the projected request,
trajectory, Judge, and canonical embedding content to the configured service.

## Run the Three-Family Gate

Create the strict provider profile described in [Shadow Evaluation and
Evidence](/router/shadow-evaluation-and-evidence#run-opt-in-live-provider-validation).
Use `provider = nvidia_inference`, the exact Chat Completions, Responses, and
Messages paths, `INFERENCE_API_KEY`, the candidate model above, the Judge model
above, and `judge_temperature = 1.0` for all three profiles.

Run the one ignored test explicitly:

```bash
NEMO_RELAY_RUN_ROUTER_LIVE_PROVIDER_TESTS=1 \
NEMO_RELAY_ROUTER_LIVE_PROVIDER_CONFIG=/absolute/path/providers.json \
cargo test -p nemo-relay-router --all-features \
  'scheduler::tests::live_provider_tests::live_three_family_provider_evidence_is_correlated_and_secret_free' \
  -- --ignored --exact --test-threads=1
```

The gate permits exactly one candidate and one initial Judge call per family.
It requires a complete correlated evidence graph, unchanged frozen anchor
evidence, valid foreign keys and SQLite integrity, and no credential bytes in
the database or its sidecars. It does not print provider request or response
bodies.

## Configure the CLI Host

Set the provider base and Codex command in `config.toml`:

```toml
[upstream]
openai_base_url = "https://inference-api.nvidia.com/v1"
anthropic_base_url = "https://inference-api.nvidia.com/v1"

[agents.codex]
command = "codex"
```

Start from the complete Shadow configuration in [Router
Configuration](/router/configuration#configure-shadow-warm-up), then use these
provider-specific fields in the sibling `plugins.toml`:

```toml
[components.config]
allow_remote_embedding_egress = true

[[components.config.embedders]]
id = "nvidia-text-embedding-3-large"
base_url = "https://inference-api.nvidia.com/v1"
model = "azure/openai/text-embedding-3-large"
provider_revision = "PINNED_DEPLOYMENT_REVISION"
dimensions = 3072
timeout_ms = 55000
api_key_env = "INFERENCE_API_KEY"

[components.config.pools.judge]
model = "openai/openai/gpt-5.5"
model_revision = "PINNED_DEPLOYMENT_REVISION"
temperature = 1.0

[components.config.pools.learning]
version = 1
embedder = "nvidia-text-embedding-3-large"

[[components.config.pools.candidates]]
id = "deepseek-v4-pro"
model = "nvidia/deepseek-ai/deepseek-v4-pro"
model_revision = "PINNED_DEPLOYMENT_REVISION"
cost_rank = 0
```

Keep every other required Judge and pool field from the complete example. The
revision string is an operator-pinned deployment identity; do not use a moving
label such as `latest`.

Validate without provider traffic:

```bash
nemo-relay --config /absolute/path/config.toml doctor --json
```

Doctor must report passed plugin validation, Router registration, native
SQLite and `sqlite-vec`, and the buffered V2 bridge before a paid run.

## Run Codex Through Relay

Map the NVIDIA key to the OpenAI-compatible upstream credential expected by
the CLI gateway, then launch a real Codex session:

```bash
export OPENAI_API_KEY="$INFERENCE_API_KEY"
nemo-relay run --agent codex --config /absolute/path/config.toml -- \
  codex exec --ephemeral --sandbox read-only \
  --model openai/openai/gpt-5.5 \
  "Respond with exactly NEMO_RELAY_CODEX_ACCEPTANCE_OK and do not call tools."
```

Codex uses a streaming Responses request. Streaming is intentionally
Router-ineligible, so this command validates the real shell launch, provider
authentication, CLI gateway, managed streaming path, Router activation, and
graceful shutdown. It does not claim delayed replay eligibility.

## Exercise Buffered Replay

Run the same built CLI as a loopback gateway:

```bash
export OPENAI_API_KEY="$INFERENCE_API_KEY"
nemo-relay --config /absolute/path/config.toml --bind 127.0.0.1:4040
```

In another shell, send a non-streaming request whose anchor model matches the
configured pool:

```bash
curl --silent --show-error \
  http://127.0.0.1:4040/v1/responses \
  -H 'Content-Type: application/json' \
  -H 'x-nemo-relay-session-id: router-real-provider-check' \
  -d '{
    "model": "openai/openai/gpt-5.5",
    "input": "Return a concise Router acceptance response.",
    "temperature": 1.0,
    "max_output_tokens": 512,
    "stream": false
  }'
```

Send a second request with the same session ID when the pool closes its horizon
after one future Primary completion. Otherwise, wait for the configured
deadline and expect the evaluation to be marked partial. Keep the gateway
running until the candidate, Judge, and embedding work drains.

Use only the supported inspection boundary to verify the result:

```bash
nemo-relay --config /absolute/path/config.toml router status --json
nemo-relay --config /absolute/path/config.toml router evidence list --json
```

A successful complete sample reports `terminal_class = completed`, a Judge
quality label, and `vector_state = ready`. A provider timeout or transport
failure has no quality label and must leave the already returned anchor
response unchanged. A later healthy sample can proceed after the local
dependency cool-off without disabling unrelated candidates or pools.

Stop the gateway with `Ctrl+C`. Restart it with the same config and confirm
that `router status` reports schema version 7 and current database state. A
separate `router status` or evidence process may read the WAL database while
the gateway owns the writer, which exercises the supported multi-process read
boundary.

## Use the Supported Database

Router has no MySQL backend. Its durable authority is a project-local SQLite
file in WAL mode with the bundled `sqlite-vec` index. `database_path` accepts
only a relative or local absolute file path and rejects database URIs. Do not
substitute MySQL, PostgreSQL, a network filesystem, or a remote SQLite service
for this acceptance workflow.

Treat the Router database as sensitive application data. Keep it owner-only,
use the Router inspection and export commands instead of direct SQL, and
remove temporary acceptance data according to your retention policy.
